# AI 장애 시 DB 커넥션 점유 시간 비교 결과

측정일: 2026-10-13 (Asia/Seoul)

## 결과

실제 PostgreSQL에 연결하여 Spring JPA 트랜잭션 전체에 AI 호출을 포함한 비교군과, DB 조회/저장 트랜잭션 밖에서 AI를 호출한 비교군을 측정했다.
이는 일기 AI 피드백 흐름을 단순화한 통제 실험이며, Hear 서비스 API 또는 PR #48 전후 버전을 직접 실행한 측정이 아니다.

| 지표 | 전체 트랜잭션 (inside) | 분리 (split) | 감소율 |
|---|---:|---:|---:|
| 요청당 커넥션 점유 시간 평균 | 3,021.232 ms | 5.219 ms | 99.83% |
| 요청당 커넥션 점유 시간 p95 | 3,032.806 ms | 11.332 ms | 99.63% |
| 커넥션 획득 대기 시간 p95 | 6,039.843 ms | 6.739 ms | 99.89% |

분모는 각 모드의 실패 작업 90건이다. 각 작업에서 커넥션 대여는 정확히 1회였다.
획득 대기 시간 p95의 표본 단위는 커넥션 대여이며, 이번 실험에서는 작업 수와 같다.
대기 p95는 선택한 풀 크기와 부하 모델에 민감하다. 일반적인 서비스 성능 개선율로 사용하지 않는다.

AI 호출 직전 모든 inside 작업은 커넥션 1개와 활성 트랜잭션을 보유했다.
모든 split 작업은 커넥션 0개, 활성 트랜잭션 없음 상태였다.
따라서 AI의 3초 지연이 inside에서는 점유 시간에 포함됐고 split에서는 포함되지 않았다.
API 자체의 3초 AI 지연을 제거한 결과가 아니다.

## 회차별 결과

| 회차 | 모드 | 점유 평균 ms | 점유 p95 ms | 획득 대기 p95 ms |
|---|---|---:|---:|---:|
| 1 | inside | 3,024.658 | 3,047.462 | 3,046.505 |
| 1 | split | 6.046 | 11.071 | 6.991 |
| 2 | inside | 3,019.332 | 3,027.607 | 12,082.190 |
| 2 | split | 5.907 | 12.650 | 6.879 |
| 3 | inside | 3,019.706 | 3,032.806 | 6,039.565 |
| 3 | split | 3.704 | 7.274 | 5.511 |

inside 획득 대기는 회차별 변동이 컸다. 닫힌 부하 모델에서 커넥션 반환 직후 작업자의 다음 작업이 대기 중인 작업보다 먼저 획득할 수 있어, 대기 시간은 모드별 점유 시간만큼 안정적이지 않았다.
이 설명은 원시 표본에서 관찰한 대기 분포에 대한 해석이며, 풀 내부 스케줄링을 별도 추적하지는 않았다.

## 환경과 방법

- Windows, Intel Core 5 120U, 메모리 약 16GB, Java 21.0.9.
- PostgreSQL 18.4 / JDBC 42.7.8, HikariCP 6.3.3, Spring ORM 6.2.16, Hibernate 6.6.42.Final.
- DB `hear_test`, 실험 테이블 `hear_tx_bench.diary`, 실험 행 1개.
- 커넥션 풀 5개, 작업자 10개, 획득 타임아웃 20초.
- 로컬 HTTP 서버가 3초 대기 후 500 응답. HTTP 타임아웃 10초, 재시도 0회.
- 모드별 30건 × 3회 = 90건, 전체 180건. 실행 순서를 회차별로 교대.
- 요청당 동일한 행 조회 1회. 실패하면 저장 로직에 도달하지 않음.
- 워밍업/기능 검사: 모드별 정상 1건·실패 1건, 측정에서 제외.
- `getConnection()` 호출/반환과 `close()` 완료를 `System.nanoTime()`으로 계측.
- p95: nearest-rank, 오름차순 `ceil(N × 0.95)`번째 값. 전체 원시 표본으로 집계.

## 검증

- 모든 측정 작업은 의도한 AI 500으로 종료: 180/180.
- AI HTTP 호출 수 180회: 추가 재시도 없음.
- 커넥션 대여 기록 180개, 작업별 1개, 반환 누락 없음.
- AI 호출 직전 커넥션 수와 활성 트랜잭션 상태 검증 통과.
- 정상 응답 경로의 실제 DB 저장 및 실패 경로의 데이터 미변경을 별도 `--verify-only` 실행으로 재검증.
- Python 표준 라이브러리로 CSV에서 평균/p95를 재계산하여 요약과 0.001ms 이내 일치 확인.
- 종료 후 실험 행 `content=fixture`, 남은 실험 연결 없음 확인.

재현 절차는 `../README.md`, 원시 데이터는 `leases.csv`와 `requests.csv`, 요약은 `summary.csv`, 환경 기록은 `environment.json`에 있다.
